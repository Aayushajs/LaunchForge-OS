Monitoring and logs

Server and service metrics, live logs, log shipping and notifications.

Server metrics#

Monitoring in the sidebar shows CPU, memory, disk and network of the server over time, collected by the LaunchForge metrics agent. Configure retention and alert thresholds under Settings → Web Server → Monitoring for the local server, or per remote server.

Host monitoring belongs to the platform workspace. Tenant workspaces on a public platform do not see it.

Metrics are always fetched by the dashboard from the agent's configured address with its token; the browser never supplies the URL.

Service metrics#

A service's Monitoring tab shows CPU, memory, network and disk I/O of its containers as live charts.

Logs#

Where What
Service → Logs Live and recent container logs, with search.
Service → Deployments The build log of each deployment.
Requests (platform workspace) The Traefik access log: which hosts and paths are called, response codes and timings.

Shipping logs and metrics#

Settings → Logs & Metrics sends logs and metrics to Datadog, Grafana Loki, Elasticsearch, Better Stack, New Relic, Splunk, CloudWatch, InfluxDB or any Prometheus remote-write endpoint.

Notifications#

Settings → Notifications → Add connects a channel:

  • Slack, Discord, Telegram, Microsoft Teams, Mattermost, Lark
  • Gotify, ntfy, Pushover
  • Email (SMTP or Resend)
  • A custom webhook

Then choose the events to send: deploy succeeded, build failed, database backup, volume backup, Docker cleanup, server restart, and CPU or memory threshold.

Usage#

What each workspace reserves and actually uses is on Settings → Usage & Quotas. See Usage and quotas.
