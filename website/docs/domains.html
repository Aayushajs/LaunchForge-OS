Domains and HTTPS

Custom domains with automatic Let's Encrypt certificates, path routing, redirects and ownership rules.

Add a domain#

Open the service, then Domains → Add Domain:

Field Meaning
Host app.example.com. Internationalized names are accepted.
Path Route only this path prefix to the service (/api). Strip path removes it before forwarding.
Internal path A prefix added before forwarding.
Container port The port the app listens on inside the container.
HTTPS Redirect HTTP to HTTPS and serve a certificate.
Certificate provider Let's Encrypt (automatic), None, or Custom (uploaded under Settings → Certificates).

Then create a DNS A or AAAA record for the host pointing at the server, or a CNAME to another name that does.

Certificates#

Let's Encrypt issues the certificate over HTTP on the first request after DNS resolves, and renews it automatically. Port 80 must be reachable.

Note

If the browser warns about the certificate, DNS probably did not resolve to the server when the domain was added. Fix DNS, then edit and save the domain to retry.

To use your own certificate, upload the certificate and key under Settings → Certificates, then pick it on the domain.

Generated sslip.io domains#

Generate sslip.io domain creates a hostname like site-1a2b3c-203-0-113-10.sslip.io that resolves to your server without any DNS setup. It is HTTP only and meant for testing.

Ownership rules#

  • A hostname is owned by the first workspace that routes it. Another workspace on the same installation cannot add the same host or a path under it (… is already in use by another workspace).
  • Inside one workspace, a host can be split by path between services (example.com/ to the web app, example.com/api to the API), but each host and path goes to one service.
  • Hosts are compared case-insensitively, without a trailing dot, and in punycode, so Example.com. and example.com are the same host.
  • Duplicating a project skips domains the original still uses.

Redirects, basic auth and middlewares#

Under the service's Advanced tab:

  • Redirects: regex redirects, for example www to the bare domain.
  • Security: HTTP basic authentication at the proxy.
  • Traefik: view and edit the service's generated router configuration. Middlewares are defined in Traefik File System.

The dashboard's own domain#

Settings → Web Server sets the domain, Let's Encrypt email and HTTPS for the dashboard itself. Once it is served over HTTPS you can close port 3000.

DNS providers#

Settings → DNS Providers connects Cloudflare, Route 53, Porkbun, Infomaniak or OVH, so LaunchForge can create the DNS record for a domain for you.

Free domains#

No domain yet? DuckDNS and is-a.dev give free subdomains that work with Let's Encrypt. See Run it for free.

Not yet supported#

  • DNS TXT ownership verification.
  • Wildcard certificates through the DNS-01 challenge.
  • A platform wildcard domain that gives every app an address automatically. A wildcard DNS record still works: see Run a public platform.
