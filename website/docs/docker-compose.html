Deploy

Docker Compose

Run multi-container apps from a compose file, start from a template, and see what the workload policy allows.

Compose services#

Create a Compose service when an app needs several containers, such as a web server, a worker and a cache.

  • Source: the same Git providers as applications (with the path to the compose file), or a compose file written in the dashboard (Raw).
  • Compose type: docker-compose runs plain containers on one server; stack runs docker stack deploy on the Swarm and honours deploy: options.
  • Domains work per compose service: pick the service name and its port, and LaunchForge adds the routing labels.
  • Isolated deployment (Advanced) puts the stack on its own network with unique names and namespaced volumes, so two copies of the same file never collide.
  • Containers lists every container of the stack, with logs and a terminal.
  • Environment variables are written to a .env file next to the compose file.

Workload policy#

Before a compose stack is deployed, LaunchForge checks it. The deployment is rejected, with every violation listed in the log, if any service uses one of these:

Not allowed Why Use instead
privileged: true Full access to the host Specific, harmless capabilities
network_mode, pid, ipc, uts, userns_mode, cgroup set to host or container:… Escapes container isolation or joins another workspace's containers The default network; service:<name>
cap_add of SYS_ADMIN, NET_ADMIN, SYS_PTRACE, SYS_MODULE, ALL, … Each is close to root on the host NET_BIND_SERVICE and other low-risk capabilities are fine
devices Direct hardware access –
security_opt with unconfined or label:disable Disables kernel protections –
Bind mounts of /, /etc, /proc, /root, /var/lib/docker, any docker.sock, … Host takeover Named volumes, or paths under the operator's allowed roots
~/… bind mounts, or ../ outside the project Reads files outside the project Paths inside the repository
include: or extends: { file: … } Pulls in files that are not checked Put all services in one file
Raw traefik.* routing labels Could claim another workspace's hostname Add a domain in the dashboard

The same bind-mount rules apply to application volumes. A rejected file shows up in the deployment log as:

text
Compose file rejected by the workload policy: …

Warning

Operators of single-owner installations who trust every user can turn the policy off with WORKLOAD_POLICY=permissive, or allow raw Traefik labels with ALLOW_COMPOSE_TRAEFIK_LABELS=true. Do not do either on a server shared with people you do not trust.

Templates#

Create Service → Template offers one-click stacks from the template catalog: databases, CMSs, analytics, monitoring and more, such as WordPress, Plausible, n8n, Uptime Kuma or Supabase. Templates are compose stacks, so the workload policy applies to them too.

AI-assisted setup#

Create Service → AI generates a compose file from a description, for you to review and deploy. It needs an LLM provider under Settings → AI: OpenAI, Anthropic, Azure, Mistral, Cohere, DeepInfra, Ollama or any OpenAI-compatible endpoint.
