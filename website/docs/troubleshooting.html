Troubleshooting

Every error message and what to do about it, plus answers to common questions.

Error messages#

Message Meaning Fix
Deployment failed: the new version was not running and healthy after 120s The container never started or its health check never passed Read the Logs tab; check the port and start command; raise DEPLOY_HEALTH_TIMEOUT_SECONDS for slow apps
Deployment failed: the new version failed and Swarm rolled back … The release started but failed; the previous version is still live Fix and redeploy
Deployment failed: the container keeps crashing: … The container exited on start three times The error after the colon is the container's exit reason
Build timed out after 3600s The build exceeded BUILD_TIMEOUT_SECONDS Cache dependencies, use a build server, or raise the limit
Compose file rejected by the workload policy: … A forbidden setting See the workload policy
Bind mount rejected: mounting /etc from the host is not allowed A system path in a volume Use a named volume
Memory quota exceeded: this service needs 512 MB but only 256 MB … is left The workspace quota is reached Lower limits, remove services, or ask the operator
This workspace can have at most N applications Count quota Same as above
example.com is already in use by another workspace Another workspace routes this host Use another host, or have them remove it
example.com/api is already routed to another service The same host and path is used twice in your workspace Change the path or remove the old domain
You are not authorized to use this Git provider (or server, registry, SSH key) The resource belongs to another workspace, or is private to another member Use your own; ask the owner to share it with the workspace
Invalid webhook signature (401) The Git host's secret is not the webhook token Set the secret to the token from the URL, or remove it
Server … has no SSH key The server's key was deleted Add a key under Settings → SSH Keys and select it on the server

Deployed site problems#

What you see Cause and fix
Build log ends with npm ERR! missing script: build Nixpacks runs npm run build. Add a build script, or use the Static build type for plain HTML.
Site shows 404 page not found The domain's container port does not match the port the app listens on. Fix it in Domains.
Site shows Bad Gateway The container is starting or crashed. Check Logs; the app must listen on 0.0.0.0, not localhost.
Browser warns about the certificate DNS did not resolve to the server when the domain was added. Fix DNS, then edit and save the domain to retry.
Deployment stuck on health check The health check URL or port is wrong, or the app takes longer than StartPeriod to boot.
React routes 404 on refresh Use the Publish directory option (nginx falls back to index.html), not npm start.
A fresh Oracle Cloud server is unreachable Oracle's Ubuntu images block ports in iptables as well as in the security list. See Run it for free.

FAQ#

Is my data encrypted?#

Secrets (environment variables, database passwords, SSH keys, Git tokens, registry and S3 keys, certificate keys) are encrypted at rest with AES-256-GCM. Keep the encryption key, a Docker secret created by the installer, with your backups.

I forgot my password#

Use Forgot password? on the sign-in page. If the server has no email set up, run this on the server and sign in with the password it prints:

bash
docker exec $(docker ps -qf name=dokploy.1) node dist/reset-password.mjs you@example.com

GitHub says the hook URL is not reachable#

GitHub only accepts webhooks it can reach from the internet. On a local or private address, LaunchForge creates the GitHub App without webhooks: repositories connect and deploy, but pushes do not deploy on their own until the dashboard has a public domain (Settings → Web Server).

Can two teams share one server safely?#

Yes, for routine use: workspaces cannot see each other's resources, take each other's domains, mount the host or exceed their quotas. Only the platform workspace can administer the server itself. Before opening sign-ups to strangers, read the security checklist.

Does a restart lose deployments?#

No. Queued deployments are stored in the database and resumed; a build that was running is restarted.

How do I update LaunchForge?#

Run sudo bash install.sh upgrade. It backs up the database first and rolls back if the new version is unhealthy. See Installation.

Where are the files?#

Configuration and build logs are in /etc/dokploy; data is in Docker volumes.
