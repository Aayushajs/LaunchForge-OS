Deploy

Environment variables

Runtime variables, shared variables and build-time settings, all encrypted at rest.

Service variables#

Open the service's Environment tab and add variables one per line:

env
NODE_ENV=production
DATABASE_URL=postgres://app_user:<password>@postgres-crimson-river-a1b2c3:5432/app_db

All values are encrypted at rest.

Shared variables#

Projects and environments have their own Environment button. Variables set there are available to every service below, so shared settings live in one place. Reference them from a service as:

text
${{project.NAME}}
${{environment.NAME}}

Build-time variables and build secrets#

Build-time variables and build secrets are separate fields from runtime variables.

  • Build arguments are passed to Dockerfile builds.
  • Build secrets are passed with BuildKit and never stored in the image.

Note

For a static site or single-page app, variables that must end up in the browser (VITE_*, NEXT_PUBLIC_*) are read at build time. Redeploy after changing them.

Compose stacks#

For a Docker Compose service, the environment variables are written to a .env file next to the compose file.

External secret stores#

Settings → Secrets connects an external secret store, and its values can be referenced in environment variables.

Connecting to a database#

A database's Internal connection URL is the usual thing to put in an application's environment, for example as DATABASE_URL. See Databases.
