Databases

Managed PostgreSQL, MySQL, MariaDB, MongoDB, Redis and libSQL, running next to your apps.

Create a database#

Inside an environment, choose Create Service → Database and pick an engine. You can pick the image version.

Engine Default image Internal port
PostgreSQL postgres 5432
MySQL mysql 3306
MariaDB mariadb 3306
MongoDB mongo 27017
Redis redis 6379
libSQL (Turso) ghcr.io/tursodatabase/libsql-server 8080

Choose a strong password, or generate one; it is stored encrypted. Data lives in a named Docker volume.

Connect from an application#

Services in the same workspace reach each other over the internal network by the database's app name, shown on the database's General tab:

text
postgres://app_user:<password>@postgres-crimson-river-a1b2c3:5432/app_db

Copy the Internal connection URL into the application's environment, for example as DATABASE_URL=....

Connect from your laptop#

Set an External port on the database's General tab. The database is then published on that port of the server.

Warning

Restrict the external port with your firewall, and remove it again when you are done.

Backups and restore#

Scheduled dumps to any S3-compatible storage, restores, and volume backups are covered in Backups.

Logs, monitoring and resources#

Databases have the same Logs, Monitoring and Advanced tabs as applications. Set CPU and memory limits under Advanced. In a workspace with a quota, a database without limits runs with the default limits and counts toward the workspace's memory and CPU. Creating a database fails if the workspace's database count limit is reached. See Usage and quotas.
