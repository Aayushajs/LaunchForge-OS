Platform

Installation

Requirements, what the installer does, its options, and how to upgrade or uninstall.

Requirements#

Minimum Recommended
OS Ubuntu 22.04 or 24.04, Debian 12 (x86_64 or arm64) Ubuntu 24.04
Memory 2 GB 4 GB or more
Disk 20 GB free under /var/lib 40 GB or more
Ports 80 and 443 (Traefik), 3000 (dashboard) free
Access root, or sudo

Install#

bash
curl -fsSL https://aayushajs.github.io/LaunchForge-OS/install.sh | sudo bash

The same script is also served from the repository at https://raw.githubusercontent.com/Aayushajs/LaunchForge-OS/main/scripts/install.sh.

What the installer does, in order. Every step is skipped if already done, so running it again is safe.

  1. Preflight: Linux, CPU architecture, not inside a container, RAM, free disk, ports 80, 443 and 3000.
  2. Docker: installs it with the official convenience script if it is missing.
  3. Swarm: docker swarm init, advertising the server's primary IPv4 address (override with --advertise-addr).
  4. Network: the attachable overlay network all services join.
  5. Secrets: three random 256-bit values stored as Docker secrets: the Postgres password, the session-signing secret and the encryption key for secrets at rest. Nothing is written to disk in plain text and no default password exists.
  6. PostgreSQL 16: a Swarm service with a named volume.
  7. Image: pulls ghcr.io/aayushajs/launchforge:<version> (falls back to edge until the first release).
  8. Bootstrap: runs dist/bootstrap.mjs from the image to write Traefik's configuration and start Traefik.
  9. Dashboard: a Swarm service with the secrets mounted, port 3000 published.
  10. Health check: waits up to 5 minutes for /api/health.

Then open http://<server-ip>:3000 and create the owner account. The first account becomes the platform operator, which can set quotas for every workspace.

Installer options#

Flag Default Purpose
--version <tag> latest Image tag (edge is the latest main build)
--image <repo> ghcr.io/aayushajs/launchforge Use another registry or a locally built image
--advertise-addr <ip> auto Address Docker Swarm advertises
--port <port> 3000 Dashboard port
--yes Non-interactive

On machines with less than 2 GB of RAM, the memory check can be lowered with LAUNCHFORGE_MIN_MEMORY_MB; see Run it for free.

HTTPS for the dashboard#

Point a DNS record such as deploy.example.com at the server, then set it under Settings → Web Server → Domain with a Let's Encrypt email. Traefik obtains the certificate automatically, and you can close port 3000.

Configuration#

Settings are environment variables on the dashboard service:

bash
sudo docker service update --env-add BUILD_TIMEOUT_SECONDS=1800 dokploy

Every variable is listed in the Configuration reference.

Upgrade, status and uninstall#

Download the script once, then use its subcommands:

bash
curl -fsSL https://aayushajs.github.io/LaunchForge-OS/install.sh -o install.sh
sudo bash install.sh upgrade                     # latest release
sudo bash install.sh upgrade --version <tag>     # a specific release
sudo bash install.sh status                      # what is running

An upgrade:

  1. Pulls the new image.
  2. Backs up the database to /etc/dokploy/backups/pre-upgrade-<UTC timestamp>.sql.gz, and refuses to continue if the backup is empty.
  3. Updates the dashboard service. Database migrations run automatically on start.
  4. Waits for /api/health. If the new version does not become healthy, it rolls the service back to the previous image and exits with an error. The data is untouched.
Tag Built from
X.Y.Z, X.Y, latest Release tags vX.Y.Z
edge Every push to main

To roll back by hand, run docker service rollback dokploy. If a migration must be undone, restore the pre-upgrade backup and pin the previous version with --version; see the Upgrade guide.

The platform workspace can also update from the dashboard: Update in the sidebar footer checks the latest LaunchForge release on GitHub and switches the dashboard to that image.

To remove LaunchForge:

bash
sudo bash install.sh uninstall           # removes services and secrets, keeps data
sudo bash install.sh uninstall --purge   # also deletes the database volume and /etc/dokploy

Where things live#

Configuration and build logs are in /etc/dokploy; data is in Docker volumes.
