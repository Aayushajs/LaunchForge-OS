Operate

Backups

Scheduled database and volume backups to any S3-compatible storage, restores, and backing up the platform itself.

Add an S3 destination#

Settings → S3 Destinations → Add accepts any S3-compatible bucket: AWS S3, Cloudflare R2, Backblaze B2, MinIO, Oracle Object Storage and others. Keys are stored encrypted.

Note

Oracle Cloud's free tier includes 20 GB of S3-compatible Object Storage, enough for the backups of a small installation. See Run it for free.

Schedule database backups#

  1. Open the database, then Backups → Create Backup.
  2. Pick the destination, a cron schedule (for example 0 3 * * * for 03:00 every day) and how many backups to keep.
  3. Use Run now once to confirm a file appears in the bucket.

Backups are pg_dump, mysqldump or mongodump streams, gzip-compressed and uploaded with rclone. Redis is covered by volume backups.

Restore a database#

Open the database, then Backups → Restore. Pick the destination and the file; progress streams live.

Warning

A restore overwrites the database. To inspect the data first, restore into a fresh database.

Volume backups#

The Volume Backups tab of an application or database archives a named volume to S3 on a schedule, optionally stopping the service during the copy for consistency.

Backing up the platform itself#

The dashboard's own data needs a backup too:

Data Where How
Platform database (projects, services, users, encrypted secrets) dokploy-postgres volume Settings → Web Server backups, or pg_dump below
Docker secrets (database password, auth secret, encryption key) Docker Swarm Store the encryption key somewhere safe
Traefik certificates and configuration /etc/dokploy/traefik File-level backup
Application databases Their volumes Scheduled database backups, above
Application volumes Docker volumes Volume backups, above

A manual backup of the platform database:

bash
CONTAINER=$(docker ps -q -f name=dokploy-postgres. | head -1)
docker exec "$CONTAINER" pg_dump -U dokploy dokploy | gzip > launchforge-$(date -u +%F).sql.gz

Warning

Secrets such as database passwords, SSH keys and Git tokens are encrypted with the encryption key. A database backup restored without the same key cannot decrypt them. Keep the key with your backups.

Restoring, and moving to a new server, are covered step by step in the Backup and restore guide. sudo bash install.sh upgrade also backs up the database before every upgrade; see Installation.
